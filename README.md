# AstrBot 打卡积分商店

项目地址：[GitHub 仓库](https://github.com/l52312516-cell/astrbot_plugin_checkin_shop)

<img src="logo.png" alt="AstrBot 打卡积分商店插件图标" width="180">

## 这是什么

这个插件解决的是"群里靠打卡攒积分、再用积分换东西"这一整条链路：每天打卡拿积分，积分攒够了引用一条消息就能兑换商品，商品的增删改和积分规则全部在 AstrBot 后台的插件页里点几下就能改。

一次兑换的完整流程是：

```text
用户：/打卡                        → 今天 +10 分（可配置固定/随机）
用户：/商店                        → 图片：我的积分 + 可兑换 / 暂不可兑换商品
用户：/兑换商品 可乐                → 机器人：是否确认兑换「可乐」商品？请引用本条消息回复 是/否
用户：（引用上面那条回复）是        → 扣分、扣库存、生成一条「待发放」记录
管理员：插件页「兑换记录」标记已发放
```

插件只负责记账和出图，**不负责发货**。兑换成功后生成的是一条 `待发放` 记录，由管理员在后台标记为 `已发放` 或 `已取消`（取消会把积分和库存退回去）。

## 功能一览

- 每日打卡，积分模式可在后台切换：**固定积分 / 随机区间 / 自定义列表（可带权重）**。
- 连签奖励：每连续 N 天额外加一笔积分。
- 每天的重置小时可配置，凌晨活跃的群可以把"新的一天"推到 4 点。
- `/商店` 出图：顶部是本人积分，下面分成 `● 可兑换` 与 `○ 暂不可兑换` 两组；不可兑换的商品直接标出原因（积分不足还差多少、已售完、超出限购、已下架）。
- `我的积分` / `积分榜` 同样出图；出图失败会自动降级成纯文本，不会因为渲染问题吞掉回复。
- 兑换必须二次确认：机器人给出确认提示，用户**引用那条消息**回复 `是`/`否` 才生效；确认超时（默认 60 秒）自动作废。
- 商品想加就加、想删就删；存在 `待发放` 记录时删除会退化成"下架"，不会丢历史账。
- 后台插件页支持商品增删改、上传商品图、调整用户积分、标记兑换状态、一键预览商店图。
- 图片由本地 Pillow 渲染，内置 Noto Sans CJK SC 字体，**不联网、不依赖 html 渲染服务**。

## 版本与要求

- 插件版本：`v1.0.0`
- AstrBot 版本：`>=4.16,<5`
- Python 依赖：`Pillow>=9.0`（Pillow 缺失或字体损坏时，命令自动降级为纯文本）
- 支持平台：`aiocqhttp`、`qq_official`、`telegram`、`webchat`

## 安装与首次使用

1. 三选一装上去：
   - 在 AstrBot 后台用 GitHub 仓库地址安装；
   - 在后台"插件"页直接上传发布包 `astrbot_plugin_checkin_shop-v1.0.0.zip`（打包方式见文末"打包发布"）；
   - 把源码目录放进 `data/plugins/`，目录名保持为 `astrbot_plugin_checkin_shop`。

   装完在后台重载插件。
2. 打开插件详情里的插件页（`pages/shop`），默认停在**商品管理**页，先点"新增商品"加几个商品，填名称、价格（积分）和可选的库存 / 限购 / 分类 / 描述。
3. 到"打卡规则"页选积分模式（固定 / 随机区间 / 自定义列表），需要的话打开连签奖励。
4. 在群里发 `/打卡`、`/商店` 试一下；确认图片能正常出。

> 首次加载时，插件配置页（`_conf_schema.json`）里的值只会**初始化**一次运行数据。之后所有改动都请在插件页里做，直接改配置页的旧值不会覆盖已有的运行数据（详见"数据与存储"）。

## 指令一览

默认唤醒前缀是 `/`（AstrBot 的 `wake_prefix` 配置）。@ 机器人、私聊、以及**引用机器人消息**时不需要前缀。

| 指令 | 别名 | 说明 |
| --- | --- | --- |
| `/打卡` | `/签到` | 每天一次，按当前积分规则发积分 |
| `/商店` | — | 出图：本人积分 + 可兑换 / 暂不可兑换商品 |
| `/我的积分` | `/积分` | 出图：本人积分、连签、最近 7 天记录 |
| `/积分榜` | `/排行榜` | 出图：本平台（或全平台）积分排行 |
| `/兑换商品 可乐` | `/兑换 可乐` | 发起兑换，机器人回复确认提示 |

关于兑换指令的写法：AstrBot 的标准指令要求"指令名 + **空格** + 参数"，所以要写成 `/兑换商品 可乐`，商品名本身可以带空格（`/兑换商品 冰镇 可乐`）。之所以不做成"连写也能认"的自定义过滤器，是因为 AstrBot 的指令注册表只认标准指令——用自定义过滤器的指令在 `/help` 和 WebUI 的「指令管理」页里会**看不见**，也不能重命名或按会话禁用。现在五条指令都在注册表里，待遇一致。

## 兑换确认

机器人的确认提示长这样：

```text
是否确认兑换「可乐」商品？
需要 30 积分。
请引用本条消息回复 是/否（60 秒内有效，编号 SHOP-4F2A19）
```

用户需要**引用这条消息**回复 `是` 或 `否`。`是` 一侧还接受 `好`、`好的`、`确认`、`确定`、`y`、`yes`、`ok`；`否` 一侧接受 `取消`、`不要`、`算了`、`不`、`n`、`no`。

为什么要引用：插件不认识"随便回一个是"，必须能证明这条回复是针对本次确认的。判定按三层兜底，任何一层命中就算：

1. 引用的正文里带有本次的编号（`SHOP-XXXXXX`）；
2. 引用的是机器人发出的那条确认消息（各平台给得出来的引用 ID 会记下来）；
3. 引用的发送者是机器人本人。

三层都没命中时，回复会被当成"不是本次兑换确认"处理，不会扣分。

另外有两个容易踩的点：

- 确认期间商品涨价、下架、被删、库存被人抢完，或用户把积分花掉了，确认时会**再次校验**并拒绝，不会按旧价格成交。
- 确认请求存在内存里，插件重启或重载后作废，重新发一次 `/兑换商品 可乐` 即可。

## 后台插件页

| 标签页 | 能做什么 |
| --- | --- |
| 商品管理 | 新增 / 编辑 / 删除商品，上传商品图，拖动排序，一键预览商店图 |
| 打卡规则 | 固定 / 随机 / 自定义积分，权重，连签奖励，重置小时 |
| 用户积分 | 搜索用户，手动加/扣/设为指定积分（会写进流水） |
| 兑换记录 | 按状态筛选，标记 `已发放` / `已取消`（取消可退回积分与库存） |
| 展示设置 | 商店标题与副标题、积分榜长度与范围、确认超时、重置小时、卡片宽度与字号 |

顶部一排统计卡显示用户数、上架/全部商品数、今日打卡人数、流通积分、兑换总数与待发放数。

几点说明：

- 商品图上传后会存到插件数据目录的 `products/` 下，页面通过接口读回为 base64 展示（插件页在 iframe 里，图片请求带不上登录态）。
- "预览商店图"是下载一张 PNG，不是弹窗预览——浏览器会把它放到下载栏。
- 页面里的表单保存后会自动刷新顶部统计，不会覆盖你还没提交的输入。

## 配置项

配置页（`_conf_schema.json`）的值只在**首次初始化**时写入运行数据。之后的日常调整请用插件页。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `checkin_mode` | `fixed` | 打卡积分模式：`fixed` / `random` / `custom` |
| `checkin_fixed` | `10` | 固定模式每次打卡的积分 |
| `checkin_random_min` / `checkin_random_max` | `5` / `20` | 随机区间（含两端） |
| `checkin_custom_points` | `[5,10,20]` | 自定义列表 |
| `checkin_custom_weights` | `[]` | 自定义权重；留空等概率，填了必须与列表等长 |
| `streak_bonus_enabled` | `true` | 是否启用连签奖励 |
| `streak_bonus_every` | `7` | 每连续多少天给一次奖励 |
| `streak_bonus_points` | `50` | 连签奖励积分 |
| `reset_hour` | `0` | 每天几点算"新的一天"；填 4 表示 0:00~3:59 仍算前一天 |
| `leaderboard_size` | `20` | 积分榜取前几名 |
| `leaderboard_scope` | `platform` | `platform` 只看本平台，`global` 看全平台 |
| `points_scope` | `platform_user` | 目前按"同平台用户共享"记账；`conversation` 预留给会话隔离模式 |
| `confirm_timeout_seconds` | `60` | 兑换确认有效期（秒） |
| `shop_title` / `shop_subtitle` | `积分商店` / … | 商店卡片上的标题与副标题 |
| `render_width` | `1080` | 卡片宽度（像素） |
| `render_font_size_base` | `0` | 卡片基础字号，0 表示按宽度自动算 |
| `render_font_path` | 空 | 自定义字体路径；留空用内置字体 |

## 数据与存储

运行数据是一份 JSON，放在 AstrBot 的插件数据目录下：

```text
data/plugin_data/astrbot_plugin_checkin_shop/
├── shop.json          # 全部运行数据：设置、打卡规则、用户、商品、兑换记录
├── render/            # 渲染缓存（按内容哈希 + 30 分钟分桶复用）
└── products/          # 后台上传的商品图
```

`shop.json` 里的内容是唯一事实来源，`_conf_schema.json` 只在文件不存在时提供初始值。写盘用"整份快照 + 临时文件 + `os.replace`"的方式，配合一把全局锁，避免打卡与兑换并发时把账写坏。文件被外部改坏时会把坏文件改名成 `shop.json.corrupt.<时间戳>` 再重建，不会直接崩。

用户积分按 `平台:用户ID` 记账，同一平台的不同群共享同一份积分；积分榜默认也按平台隔离。

## 图片与字体

三张卡片都由 Pillow 同步绘制，字体是插件内置的 **Noto Sans CJK SC Regular**（`resources/NotoSansCJKsc-Regular.otf`，未做任何修改，遵循 SIL Open Font License 1.1，许可证文本见 `resources/OFL.txt`，来源与替换说明见 `resources/NOTICE.md`）。

- 想换字体：把 `render_font_path` 指向系统字体（例如 `C:\Windows\Fonts\msyh.ttc`）。
- 不想带字体：删掉那个 `.otf` 文件即可，插件会降级为纯文本回复。

卡片里刻意没有使用 emoji：内置的等宽 CJK 字体不含彩色 emoji 字形，画出来会是空心方块，所以分组标题用的是 `●` / `○` 加颜色区分。

## 常见问题

**为什么回复"是"没反应？** 确认必须**引用**机器人那条确认消息。没引用、引用了别的消息、或者超过 `confirm_timeout_seconds` 都会拒掉；超时后重新发一次 `/兑换商品 可乐` 即可。若提示"当前没有等待确认的兑换请求"，说明本次确实没有待确认的请求（比如插件重启过）。

**为什么群里发 `兑换商品可乐` 没反应？** 指令名后面要加空格：`/兑换商品 可乐`。另外这类指令同样需要先唤醒机器人：用 `/` 前缀、@ 机器人，或引用机器人的消息再说。

**积分是每个群分开算的吗？** 不是。默认按 `平台:用户ID` 记账，同一平台跨群共享；积分榜默认也按平台取。

**打卡的"今天"怎么算？** 默认按本地时间 0 点切分；`reset_hour` 设成 4 之后，凌晨 0:00~3:59 打的卡仍算前一天，不会被算成新的一天。

**兑换后为什么没人给我发货？** 插件只记账。请让管理员在插件页"兑换记录"里把记录标记为 `已发放` 并线下发货。

**删商品时提示"改为下架"？** 该商品还有 `待发放` 的兑换记录。为了保证历史账目可追溯，插件把删除退化成下架；等这些记录处理完再删即可。

**图片没出来 / 只有文字？** 说明渲染失败（缺 Pillow、字体被删、自定义字体路径写错），插件已自动降级为纯文本回复；日志里会有 `[打卡商店] 图片渲染失败` 的记录。

**在插件配置页改了固定积分，为什么不生效？** 配置页的值只在首次初始化 `shop.json` 时使用。请在插件页"打卡规则"里改。

## 手动验收清单

本仓库自带测试只覆盖到"插件接线 + 业务逻辑 + 页面接线"，真实平台上的收发消息需要在你自己那台 AstrBot 上跑。建议按下面顺序过一遍：

1. `/打卡` 连续发两次：第一次成功、第二次提示已经打过卡。
2. 插件页改积分模式为"随机区间"，保存；换一天再打卡，看积分是否落在区间内。
3. `/商店`：确认出图，且"可兑换/暂不可兑换"分组、`还差 N 分` 的提示与后台数据一致。
4. `/兑换商品 可乐`：机器人给出确认提示；**不引用**直接回"是"，应被拒绝。
5. 引用确认消息回"是"：积分和库存按预期变化，后台"兑换记录"出现一条 `待发放`。
6. 在后台把该记录标记为 `已取消`（勾选退回积分与库存），确认积分库存都回来了。
7. 后台删一个有 `待发放` 记录的商品：应提示改为下架。
8. 插件页上传一张商品图，重新 `/商店`，确认图出现在商品行里。
9. 触发一次渲染失败（例如把 `render_font_path` 指向不存在的文件）：命令仍以文字回复，不报错。

## 开发与测试

```bash
# 业务逻辑 / 存储 / 渲染 / 插件接线（需要 Python 3.10+ 与 Pillow）
python -m pytest

# 插件页接线（需要 Playwright；脚本也会直接找本机 Edge）
node tests/test_page.cjs
```

测试覆盖：时间与逻辑日切换、JSON 存储的原子写与并发、打卡与兑换的边界分支、Pillow 出图（含"内置字体不缺字"检查）、以及用最小 AstrBot 桩验证指令注册、引用解析和"发起兑换 → 引用确认 → 扣分扣库存"的完整闭环。`tests/test_page.cjs` 会起一个临时静态服务器加载插件页，用假的 bridge 驱动五个标签页并把页面截图存到 `docs/page.png`。

`docs/` 下的 `shop.png` / `points.png` / `boards.png` 由 `scripts/render_demo.py` 用固定假数据生成，可随时重跑，不依赖 AstrBot。

## 打包发布

```bash
# 产出 ../astrbot_plugin_checkin_shop-v1.0.0.zip（默认打在仓库上一级，避免产物混进源码树）
python scripts/build_release.py
```

压缩包按 AstrBot 的安装逻辑组织：`metadata.yaml` 位于**压缩包根目录**（安装器据此识别插件与目录名），`name` 是合法 Python 标识符。包含运行所需的全部文件——代码、`pages/shop` 插件页、`_conf_schema.json`、i18n、内置字体与 OFL 许可；**不包含** `tests/`、`scripts/`、`docs/`、`pytest.ini` 等开发文件。

打包脚本会立刻回读产物自检：元数据必填字段、schema 可解析、关键文件齐全、字体在位、无缓存文件混入。
