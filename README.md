# AstrBot 打卡积分商店

项目地址：[GitHub 仓库](https://github.com/l52312516-cell/astrbot_plugin_checkin_shop)

<img src="logo.png" alt="AstrBot 打卡积分商店插件图标" width="180">

## 这是什么

这个插件解决的是"群里靠打卡攒积分、再用积分换东西"这一整条链路：每天打卡拿积分，积分攒够了引用一条消息就能兑换商品，商品的增删改和积分规则全部在 AstrBot 后台的插件页里点几下就能改。

一次兑换的完整流程是：

```text
用户：/打卡                        → 今天 +10 分（可配置固定/随机，图文一条消息）
用户：/商店                        → 图片：我的积分 + 可兑换 / 暂不可兑换商品（带编号）
用户：/兑换商品                     → 文字：商品编号菜单（01 冰镇可乐 30 积分…）
用户：/兑换 1                       → 机器人：是否确认兑换「冰镇可乐」商品？请引用本条消息回复 是/否
用户：（引用上面那条回复）是        → 扣分、扣库存、生成一条「待发放」记录
管理员：插件页「兑换记录」标记已发放   → 机器人主动私聊该用户：你兑换的「可乐」已发放完成
                                    → 若开启了邮件通知，同时给该用户发一封 SMTP 邮件
用户：/绑定邮箱 123@qq.com          → 绑定收件地址（可选；不绑定就按 QQ 号推 @qq.com）
用户：/商店帮助                     → 图片：指令、当前积分规则、兑换步骤
```

插件只负责记账、出图和通知，**不负责发货**。兑换成功后生成的是一条 `待发放` 记录，由管理员在后台标记为 `已发放`（标记后自动通知用户，并可按配置发邮件）或 `已取消`（取消会把积分和库存退回去）。

## 功能一览

- 每日打卡，积分模式可在后台切换：**固定积分 / 随机区间 / 自定义列表（可带权重）**。
- **没带唤醒前缀也不会装死**：新用户很容易直接发「打卡」（没有 `/` 也没 @ 机器人），AstrBot 的标准指令这时根本不会触发；插件用不受唤醒前缀约束的正则过滤器兜住"整条消息就是一个指令名"的情况，回一句"要用「打卡」得先唤醒机器人：发送 /打卡，或者先 @我"。带别的内容（比如"我今天打卡了"）不会触发。
- 连签奖励：每连续 N 天额外加一笔积分。
- 每天的重置小时可配置，凌晨活跃的群可以把"新的一天"推到 4 点。
- `/商店` 出图：顶部是本人积分，下面分成 `可兑换` 与 `暂不可兑换` 两组（左侧色条 + 计数胶囊）；可兑换的只显示价格，不可兑换的直接标出原因（积分不足还差多少、已售完、超出限购、已下架）。商品按区块连续编号，带商品图或按名字生成的占位色块。
- 四张卡片（商店 / 积分 / 积分榜 / 帮助）共用一套视觉规范：白底圆角面板 + 深色标题 + 浅灰说明文字、统一的区块色条与分隔线，渲染后按内容裁掉底部空白，不会拖一条长尾巴。
- **文字和图片合成一条消息**发出（`/打卡`、`/商店`、`/我的积分`、`/积分榜`、`/商店帮助` 都是），不会再出现"先一条字、再一张图"的两条消息。
- `/商店帮助` 渲染一张帮助图：指令表、当前生效的积分规则、兑换步骤；出图失败时降级成同内容的文字。
- `我的积分` / `积分榜` 同样出图；出图失败会自动降级成纯文本，不会因为渲染问题吞掉回复。
- 兑换必须二次确认：机器人给出确认提示，用户**引用那条消息**回复 `是`/`否` 才生效；确认超时（默认 60 秒）自动作废。
- 兑换记录支持 `待发放 / 已发放 / 已取消` 流转，还能**删除**；删除只清理历史，不退还积分与库存（想退积分请用"取消并返还"）。
- **账单流水**：每一次积分变动（打卡赚分、兑换扣分、取消兑换返还、管理员手动调整）都会落一条，后台可按关键词 / 类型 / 日期区间筛选、看收支汇总，并一键导出 CSV 对账。
- **发放邮件通知（SMTP）**：标记 `已发放` 时除会话提示外，还可以给该用户发一封真邮件。收件地址优先用用户自己绑定的邮箱（`/绑定邮箱 123@qq.com`），其次按「QQ 号 + `@qq.com`」推断，最后用配置里的兜底收件人；配置页里可一键"发送测试邮件"。
- 商品想加就加、想删就删；存在 `待发放` 记录时删除会退化成"下架"，不会丢历史账。删除按钮用的是**页面内确认框**（插件页 iframe 的 sandbox 不带 `allow-modals`，浏览器会静默忽略 `window.confirm()`，所以这里不依赖它）。
- 后台插件页支持商品增删改、上传商品图、调整用户积分、标记兑换状态、删除兑换记录、发送测试邮件、一键预览商店图。
- **插件页与插件配置页互通**：打卡积分模式、连签奖励、商店标题等两边都改得，规则见"配置项"。
- 唤醒前缀不是 `/` 的时候，提示语与卡片上的指令写法可以跟着改（配置项 `display_prefix`）；它**只影响显示**，不影响指令匹配。
- 图片由本地 Pillow 渲染，内置 Noto Sans CJK SC 字体，**不联网、不依赖 html 渲染服务**。

## 版本与要求

- 插件版本：`v1.2.0`
- AstrBot 版本：`>=4.16,<5`
- Python 依赖：`Pillow>=9.0`（Pillow 缺失或字体损坏时，命令自动降级为纯文本；邮件用标准库 `smtplib`，无额外依赖）
- 支持平台：`aiocqhttp`、`qq_official`、`telegram`、`webchat`

## 安装与首次使用

1. 三选一装上去：
   - 在 AstrBot 后台用 GitHub 仓库地址安装；
   - 在后台"插件"页直接上传发布包 `astrbot_plugin_checkin_shop-v1.2.0.zip`（打包方式见文末"打包发布"）；
   - 把源码目录放进 `data/plugins/`，目录名保持为 `astrbot_plugin_checkin_shop`。

   装完在后台重载插件。
2. 打开插件详情里的插件页（`pages/shop`），默认停在**商品管理**页，先点"新增商品"加几个商品，填名称、价格（积分）和可选的库存 / 限购 / 分类 / 描述。
3. 到"打卡规则"页选积分模式（固定 / 随机区间 / 自定义列表），需要的话打开连签奖励。
4. 在群里发 `/打卡`、`/商店` 试一下；确认图片能正常出。

> 打卡规则这类"两边都能改"的配置由插件统一合并：**配置页优先**（只认相对上次同步真正改动过的键，所以改回默认值也生效），插件页保存时回写配置页；从旧版本升级上来时，如果配置页还是默认值而插件页已改过，则保留插件页的值。详见"配置项"。

## 指令一览

默认唤醒前缀是 `/`（AstrBot 的 `wake_prefix` 配置）。@ 机器人、私聊、以及**引用机器人消息**时不需要前缀。下表按默认前缀写；如果你把唤醒前缀配成了别的符号，插件回复和帮助图里的指令写法可以用配置项 `display_prefix` 跟着改（见下文「指令前缀只影响显示」），**指令本身不用改**。

| 指令 | 别名 | 说明 |
| --- | --- | --- |
| `/打卡` | `/签到` | 每天一次，按当前积分规则发积分 |
| `/商店` | — | 出图：本人积分 + 可兑换 / 暂不可兑换商品（带编号） |
| `/我的积分` | `/积分` | 出图：本人积分、连签、最近 7 天记录 |
| `/积分榜` | `/排行榜` | 出图：本平台（或全平台）积分排行 |
| `/兑换商品` | `/兑换` | 不带参数：列出商品编号菜单（用户不必打字输商品名） |
| `/兑换商品 1` | `/兑换 1` | 按编号发起兑换，机器人回复确认提示 |
| `/兑换商品 可乐` | `/兑换 可乐` | 也可以直接写商品名（支持名称的一部分），两种写法都认 |
| `/绑定邮箱 123@qq.com` | `/我的邮箱` | 绑定收件邮箱（发放邮件用）；不带参数查看，填 `解绑` 清除 |
| `/商店帮助` | `/打卡帮助` | 出图：指令、当前积分规则、兑换步骤 |

所有带图的回复都是**文字 + 图片在同一条消息**里，不会拆成两条。

关于兑换指令的写法：AstrBot 的标准指令要求"指令名 + **空格** + 参数"，所以要写成 `/兑换商品 1` 或 `/兑换商品 可乐`，商品名本身可以带空格（`/兑换商品 冰镇 可乐`）。之所以不做成"连写也能认"的自定义过滤器，是因为 AstrBot 的指令注册表只认标准指令——用自定义过滤器的指令在 `/help` 和 WebUI 的「指令管理」页里会**看不见**，也不能重命名或按会话禁用。现在七条指令都在注册表里，待遇一致。

### 商品编号（序号）

`/兑换商品` 不带参数时回复的是一张**纯文本编号菜单**（省一条图片消息，翻起来也快）：

```text
积分商店 · 商品编号（当前 120 积分）
01 冰镇可乐 — 30 积分
02 体验卡 — 500 积分（还差 380 分）
03 限量手办 — 1200 积分（已售完）

把编号发给我就能兑换，例如：/兑换 1
```

- 编号 = 商品在**商店图里的那个编号**（`01`、`02`…，跨"可兑换 / 暂不可兑换"两个区块连续），后台商品表的「序号」列也是同一个号。
- 编号按**全部商品**（含下架）的顺序计算，所以下架/上架不会让其它商品的编号漂移；但**改顺序（后台的上移/下移）会改编号**，用户以最新菜单为准。确认提示里始终是真实商品名，发错号也不会兑换错东西。
- 编号写法很宽松：`1`、`01`、`#1`、`第1个`、`1号` 都认。发的编号不存在时会回一句"没有 9 号商品"并提示怎么看最新列表；编号指向的商品已下架时会明确说"已下架"，而不是含糊地说没这个编号。
- 不带编号的 `/兑换商品`、`/兑换` 也能用；旧的名称写法（`/兑换商品 可乐`）不受影响，名称匹配到多个商品时会列出各自编号引导改用编号。

## 兑换确认与发放通知

机器人的确认提示长这样：

```text
是否确认兑换「可乐」商品？
需要 30 积分。
请引用本条消息回复 是/否（60 秒内有效，编号 SHOP-4F2A19）
```

用户需要**引用这条消息**回复 `是` 或 `否`。`是` 一侧还接受 `好`、`好的`、`确认`、`确定`、`y`、`yes`、`ok`；`否` 一侧接受 `取消`、`不要`、`算了`、`不`、`n`、`no`。

为什么要引用：插件不认识"随便回一个是"，必须能证明这条回复是针对本次确认的。判定按三层兜底，任何一层命中就算：

1. 引用的正文里带有本次的编号（`SHOP-XXXXXX`）；
2. 引用的是机器人发出的那条确认消息（各平台给得出来的引用 ID 会记下来）；
3. 引用的发送者是机器人本人。

三层都没命中时，回复会被当成"不是本次兑换确认"处理，不会扣分。几个边界情况：

- **没有待确认请求时，机器人不会接你的话**：群里有人说"好"、"ok"、"不"，只要这个人名下没有待确认的兑换，插件一律放行（交给其他插件/大模型），不会回"当前没有等待确认的兑换请求"。
- **有待确认请求、但你没引用**：机器人只回一句怎么做（`请「引用」机器人那条确认消息再回复 是/否`），不会动你的积分，请求还在，照做一遍就行。
- **确认超时**：只有引用能对上那条确认消息时才会提示"已超时，请重新发送"，否则同样不打扰。
- **会话标识变了也能确认**：少数平台（或你在私聊里确认、在群里发起的）给两条消息的会话 ID 不一致时，插件会退化成"只看用户"来找待确认请求，不会因为对不上会话就报"没有请求"。

另外有两个容易踩的点：

- 确认期间商品涨价、下架、被删、库存被人抢完，或用户把积分花掉了，确认时会**再次校验**并拒绝，不会按旧价格成交。
- 确认请求存在内存里，插件重启或重载后作废，重新发一次 `/兑换 1` 即可。

管理员在插件页把记录标记为 `已发放` 的那一刻，插件会**主动给该用户发一条提示**（同一 QQ 优先走私聊，发不出去就退回用户当初发起兑换的那个会话）：

```text
小明，你兑换的「可乐」已发放完成 ✅
本次消耗 30 积分。
如果还没收到实物/权益，请联系管理员。
```

几个细节：

- 只有"第一次"变成 `已发放` 才通知，重复点按钮不会反复打扰用户。
- 兑换记录里会存下发起兑换的会话（`session` 字段）。从旧版本升上来的老记录没有这个字段，标记发放时会正常改状态，但通知不了用户——接口会如实返回"未通知用户"。
- 通知失败不会影响记录状态：状态已经改好，只是提示没发出去。
- `qq_official` 这类不支持机器人主动发消息的平台会走"退回原会话"这条路；如果连原会话都没有，就只能靠邮件或线下通知了。

### 发放邮件（SMTP）

在插件配置页填好 SMTP，并打开「启用兑换发放邮件通知」后，标记 `已发放` 时会额外发一封邮件：

```text
主题：【积分商店】兑换发放通知

小明，你的兑换已经发放完成。

商品：可乐
消耗积分：30
兑换时间：2026-10-11 10:00
兑换单号：r1

如果长时间没有收到实物或权益，请直接回复机器人联系管理员。
—— 积分商店
```

**收件地址**按顺序确定：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 用户绑定的邮箱 | 用户自己发 `/绑定邮箱 123@qq.com`；任何平台都适用 |
| 2 | 「用户号 + 默认后缀」 | 默认后缀 `@qq.com`，所以 QQ 用户 `10001` 会发到 `10001@qq.com`；后缀留空表示不做这种推断 |
| 3 | 兜底收件人 | 配置里的「兜底收件人」（一般是管理员邮箱）；没配就不发 |

SMTP 配置项（都在插件配置页，**不写进 `shop.json`**，避免把授权码复制到运行数据里）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `email_enabled` | 关 | 总开关 |
| `email_smtp_host` | 空 | 例如 `smtp.qq.com` |
| `email_smtp_port` | `465` | SSL 常用 465，STARTTLS 常用 587 |
| `email_smtp_encryption` | `ssl` | `ssl` / `starttls` / `none` |
| `email_smtp_user` | 空 | 通常填完整邮箱地址 |
| `email_smtp_password` | 空 | 配置页里以密码框显示；**QQ 邮箱要填"授权码"，不是登录密码** |
| `email_sender` | 空 | 发件人地址，留空用 `email_smtp_user` |
| `email_recipient_suffix` | `@qq.com` | 用户没绑邮箱时用来拼地址 |
| `email_fallback_to` | 空 | 推不出用户邮箱时的收件人 |

注意：

- 发送是在**线程**里跑的（`smtplib` 是阻塞库），不会卡住 AstrBot 的事件循环；单次发送超时 15 秒。
- 邮件失败**不影响**发放状态和会话通知，插件会在返回给后台的提示里写清失败原因（例如认证失败、超时、配置缺哪一项），并记一条 warning 日志（日志里不含密码）。
- 用户换邮箱不用找管理员：自己发 `/绑定邮箱 新邮箱@example.com` 覆盖，发 `/绑定邮箱 解绑` 清除。
- `qq_official` 这类平台发不了主动消息，邮件就是唯一的自动通知渠道——记得让用户绑邮箱。

| 用户积分 | 搜索用户，手动加/扣/设为指定积分（会写进流水） |
| 兑换记录 | 按状态筛选，标记 `已发放`（自动通知用户 + 按配置发邮件）/ `已取消`（可退回积分与库存），删除记录，发送测试邮件验证 SMTP |
| 账单流水 | 每一次积分变动都在这里：关键词 / 类型 / 日期区间筛选，筛选结果汇总（收入 · 支出 · 净变动），一键导出 CSV |
| 展示设置 | 商店标题与副标题、积分榜长度与范围、确认超时、重置小时、卡片宽度与字号 |

顶部一排统计卡显示用户数、上架/全部商品数、今日打卡人数、流通积分、兑换总数与待发放数。

商品管理页的几个细节：

- **序号列**就是用户在群里看到的编号（`01`、`02`…）。搜索和排序只改变"看到哪些行、按什么顺序看"，序号只跟真正的展示顺序走——所以筛选后 `01` 还是 `01`，照着编号兑换不会错。
- **搜索框**匹配名称、分类、价格、描述和编号；**分类下拉**的选项由现有商品自动收集（不新增数据字段），选「全部分类」看全部；**状态下拉**把上架/下架分开，另有「可兑换 / 已售完 / 积分不足」三种规则视角。没有结果时给的是"没有匹配的商品 + 清空筛选"的空状态。
- **点状态 pill 直接上下架**（不用开编辑弹窗），**↑/↓** 调顺序——两者都会立刻反映到商店图与用户端编号；编辑已有商品不会再改变它的位置（新增商品才排到最后）。
- 右侧显示「共 N 个 · 显示 M 个」，一眼能看出筛选掉了几行。

账单流水页的几个细节：

- 记录**四类变动**：`打卡`（收入）、`兑换`（扣分）、`返还`（取消兑换退回）、`调整`（管理员手动改分）。每条都带「变动后余额」，顺着往下读就能对账。
- **筛选**：关键词匹配昵称 / QQ / user_key / 备注；类型下拉；日期区间（含当天，`日期上界` 会补到当天 23:59:59）。右侧「筛选结果」显示的是**筛选后全部记录**的收入 / 支出 / 净变动，不是当前页的数字。
- **导出 CSV** 导的是当前筛选条件下的**全部**记录（不只是当前页），带 BOM，Excel 直接打开不乱码。
- 流水最多保留最近 1000 条（`LEDGER_LIMIT`），超出会自动裁掉最旧的；`shop.json` 里就是一个普通数组，可以自己备份。
- **升级说明**：只有装上新版本之后发生的变动才会进流水；旧版本积累的兑换记录不会自动补进流水，历史兑换请看「兑换记录」页。

界面细节：颜色走 CSS 变量，**跟随宿主 WebUI 的深色模式**（宿主没下发主题时回落到系统 `prefers-color-scheme`，`[data-theme]` 优先于系统偏好）；字号只有四档、间距是多列 4/8 的 4 个档位，六个统计卡等高；表格有吸顶表头、数字列右对齐等宽数字、长名字省略号，窄屏下表格与标签页各自横向滚动而不是把页面撑宽；状态提示是顶栏下的横幅——成功 3 秒自动消失，失败常驻且可手动关闭；表单就地校验（红框 + 字段下方原因 + 自动聚焦第一个错误）；异步按钮进行中会禁用并转圈，避免重复提交；商品/用户/兑换/规则为空时给的是空状态而不是一张空表。

几点说明：

- 商品图上传后会存到插件数据目录的 `products/` 下，页面通过接口读回为 base64 展示（插件页在 iframe 里，图片请求带不上登录态）。
- "预览商店图"是下载一张 PNG，不是弹窗预览——浏览器会把它放到下载栏。
- 页面里的表单保存后会自动刷新顶部统计，不会覆盖你还没提交的输入。
- 删除兑换记录会二次确认：`待发放` 的记录还占着用户的积分，删除**不会**退积分、回补库存，所以默认拒绝，必须先点"取消并返还"或显式确认强制删除。`已发放` / `已取消` 的记录可以直接删。
- 删除商品/兑换记录用的是**页面内确认框**，不是 `window.confirm()`：插件页跑在 `sandbox="allow-scripts allow-forms allow-downloads"` 的 iframe 里（没有 `allow-modals`），浏览器会直接忽略 `window.confirm()` 并返回 `false`，用它会出现"点了删除没反应"。确认框可以用鼠标点遮罩或按 `Esc` 取消，按"确定"才真的调接口。
- 在插件页保存打卡规则或展示设置时，插件会把这些值**回写插件配置页**，所以配置页不会一直显示旧值（提示语里会写明"已同步到插件配置页"）。
- 「展示设置」里的**指令前缀（仅显示）**只影响文案里指令的写法：改它不会让机器人接受新的唤醒前缀，也不会影响指令匹配，详见下文「指令前缀只影响显示」。

## 配置项

打卡规则和展示设置里的这些字段**插件页和配置页都能改**，两边是同一份配置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `checkin_mode` | `fixed` | 打卡积分模式：`fixed` / `random` / `custom` |
| `checkin_fixed` | `10` | 固定模式每次打卡的积分 |
| `checkin_random_min` / `checkin_random_max` | `5` / `20` | 随机区间（含两端） |
| `checkin_custom_points` | `[5,10,20]` | 自定义列表 |
| `checkin_custom_weights` | `[]` | 自定义权重；留空等概率，填了必须与列表等长 |
| `streak_bonus_enabled` | `true` | 是否启用连签奖励 |
| `streak_bonus_every` | `7` | 每连续多少天给一次奖励 |
| `streak_bonus_points` | `50` | 连签奖励积分 |
| `reset_hour` | `0` | 每天几点算"新的一天"；填 4 表示 0:00~3:59 仍算前一天 |
| `leaderboard_size` | `20` | 积分榜取前几名 |
| `leaderboard_scope` | `platform` | `platform` 只看本平台，`global` 看全平台 |
| `points_scope` | `platform_user` | 目前按"同平台用户共享"记账；`conversation` 预留给会话隔离模式 |
| `confirm_timeout_seconds` | `60` | 兑换确认有效期（秒） |
| `shop_title` / `shop_subtitle` | `积分商店` / … | 商店卡片上的标题与副标题 |
| `display_prefix` | `/` | **显示用**的指令前缀：只改提示语和卡片上指令的写法（如填 `.` 就把 `/打卡` 显示成 `.打卡`），不改实际触发。详见下文「指令前缀只影响显示」 |
| `render_width` | `1080` | 卡片宽度（像素）；只在配置页，改完重载插件生效 |
| `render_font_size_base` | `0` | 卡片基础字号，0 表示按宽度自动算 |
| `render_font_path` | 空 | 自定义字体路径；留空用内置字体 |
| `email_*`（9 项） | 关闭 | 发放邮件通知，见上文「发放邮件（SMTP）」 |

> 邮件相关的 9 个配置项只在发邮件时读取，**不会**进 `shop.json`（授权码不该出现在运行数据里），所以它们不参与下面的合并规则。

合并规则（解决"两边都改、听谁的"）：

1. **配置页优先**：插件每次加载（含在配置页保存后 AstrBot 自动热重载）都会把配置页的值写进运行数据；打卡时会顺手再同步一次，所以配置页改完马上生效。
2. **只认"改动过"的配置**：运行数据里存着一份"上次同步时的配置值"（`config_snapshot`）。只有相对上次同步**改动过**的配置键才会覆盖运行数据——所以配置页既能把值改回默认值（不会因为值恰好等于默认值而被忽略），也不会在每次加载时无谓地覆盖插件页刚保存的值。
3. **升级保护**：如果运行数据里还没有同步记录（新装，或从没有该记录的旧版本升级上来），配置页里的非默认值直接生效；若配置页仍是默认值、而运行数据已被插件页改过，则保留运行数据的值并回写配置页，不让升级把设置冲回默认。
4. **单向回写**：在插件页保存打卡规则/展示设置时，插件直接把值写回 `_conf_schema.json` 对应的配置项（不会触发二次重载），配置页随即显示新值。

`checkin_mode` 这类配置两边都改得，但**不建议同时开着两个页面改**：以最后一次保存的为准。

### 指令前缀只影响显示

有些机器人的唤醒前缀不是 `/`（AstrBot 里可以配成 `.`、`!` 之类）。这种情况下默认文案里的 `/打卡` 会跟实际操作对不上，所以在配置页加了一个 **`display_prefix`（显示用的指令前缀）**：

- 它决定**文案怎么写**：插件回复（如「发送 /商店 看看能换点什么吧～」）、`/商店帮助` 那张图、卡片上的空状态提示、"没找到商品"这类提示语，都会用你填的前缀；取值优先用运行数据（插件页保存后立刻生效，不必等配置页热重载），配置页仍是权威来源；
- 它**不决定能不能触发**：消息前缀仍然由 AstrBot 的唤醒前缀（`wake_prefix`）决定。所以填错不会让指令失效，只是文案与实际不符——**一般不用改**；
- 留空等于 `/`；最多 8 个字符（接口和页面都会拦超长值），前缀再长卡片排版也不会溢出；
- 改完最长 30 分钟内一定看到新图：卡片缓存键里带了前缀，改前缀会直接生成新图，不会命中旧缓存。

## 数据与存储

运行数据是一份 JSON，放在 AstrBot 的插件数据目录下：

```text
data/plugin_data/astrbot_plugin_checkin_shop/
├── shop.json          # 全部运行数据：设置、打卡规则、用户、商品、兑换记录、配置同步记录
├── render/            # 渲染缓存（按内容哈希 + 30 分钟分桶复用）
└── products/          # 后台上传的商品图
```

`shop.json` 是用户、商品、兑换记录和各项设置的唯一事实来源；`_conf_schema.json` 里的"打卡规则 / 展示设置"字段是它的一个**同步视图**——配置页优先，插件页保存时回写配置页（规则见上一节）。写盘用"整份快照 + 临时文件 + `os.replace`"的方式，配合一把全局锁，避免打卡与兑换并发时把账写坏。文件被外部改坏时会把坏文件改名成 `shop.json.corrupt.<时间戳>` 再重建，不会直接崩。

用户积分按 `平台:用户ID` 记账，同一平台的不同群共享同一份积分；积分榜默认也按平台隔离。每个用户记录里还有一个可选的 `email` 字段（`/绑定邮箱` 写入），用于发放邮件。

## 图片与字体

四张卡片（商店 / 我的积分 / 积分榜 / 商店帮助）都由 Pillow 同步绘制，字体是插件内置的 **Noto Sans CJK SC Regular**（`resources/NotoSansCJKsc-Regular.otf`，未做任何修改，遵循 SIL Open Font License 1.1，许可证文本见 `resources/OFL.txt`，来源与替换说明见 `resources/NOTICE.md`）。

- 想换字体：把 `render_font_path` 指向系统字体（例如 `C:\Windows\Fonts\msyh.ttc`）。
- 不想带字体：删掉那个 `.otf` 文件即可，插件会降级为纯文本回复。

卡片里刻意没有使用 emoji：内置的等宽 CJK 字体不含彩色 emoji 字形，画出来会是空心方块，所以分组标题用的是 `●` / `○` 加颜色区分。纯文字回复（例如发放通知）里的 emoji 由各家客户端自己渲染，不受此限制。

## 常见问题

**为什么回复"是"没反应？** 确认必须**引用**机器人那条确认消息。没引用、引用了别的消息、或者超过 `confirm_timeout_seconds` 都会拒掉；超时后重新发一次 `/兑换商品 1` 即可。若提示"当前没有等待确认的兑换请求"，说明本次确实没有待确认的请求（比如插件重启过）。

**为什么群里发 `兑换商品可乐` 没反应？** 指令名后面要加空格：`/兑换商品 可乐` / `/兑换商品 1`。另外这类指令同样需要先唤醒机器人：用 `/` 前缀、@ 机器人，或引用机器人的消息再说。

**为什么发「打卡」（没带 `/`、也没 @ 机器人）没反应？** 这是 AstrBot 的唤醒机制：标准指令只在消息以唤醒前缀开头（或 @ 机器人 / 私聊）时才触发，不是插件漏了处理。v1.2.0 起插件会兜一句提示告诉你该怎么发；如果你连这句提示都看不到，说明消息根本没进到 AstrBot（例如机器人没启用、会话里禁用了插件），去看 AstrBot 日志。

**发了 `/打卡` 却完全没有回复，怎么定位？** 按下面三步走，能直接分清是哪一层：

1. 在同一会话里再发一次 `/商店`（或 `/积分榜`）：如果**也不回**，问题不在打卡逻辑，而是这个会话没加载/禁用了插件——去 WebUI 的会话管理里看该会话的插件开关，以及插件是否处于启用状态。
2. 去 AstrBot 日志里搜 `[打卡商店]`：出现 `打卡成功 user=… session=…` 说明插件已经正常跑到并发出去了（那就要看消息平台那边为什么没送到）；出现 `打卡失败 user=… session=…` 说明有异常，后面跟的堆栈就是原因。
3. 日志里既没有 `[打卡商店]` 也没有异常 → 消息没有触发标准指令：检查 `wake_prefix` 是不是被改成了别的字符（默认是 `/`）、是不是 @ 了别人（第一条 @ 不是机器人时 AstrBot 不会唤醒）、或者有没有别的插件先用同名的正则/全量过滤器把这条消息吃掉了（AstrBot 里前一个处理器产出结果后事件就结束了）。

另外插件页的「兑换记录」和「用户积分」两栏随时能看到打卡有没有落库：如果日志里有"打卡成功"但后台没有记录，那就是两份数据目录不一致（插件数据目录被改过），不是你眼睛的问题。

**机器人怎么突然回我一句"没有等待确认的兑换请求"？** v1.1.0 的老毛病：没有待确认兑换时，任何人发"好/是/不/ok"都会被拦下来回这句。v1.2.0 起改为静默放行；只有在**确实有待确认请求、但你没引用**时才提示（提示里会说清怎么引用），超时提示也只在引用对得上时出现。

**积分是每个群分开算的吗？** 不是。默认按 `平台:用户ID` 记账，同一平台跨群共享；积分榜默认也按平台取。

**打卡的"今天"怎么算？** 默认按本地时间 0 点切分；`reset_hour` 设成 4 之后，凌晨 0:00~3:59 打的卡仍算前一天，不会被算成新的一天。

**兑换后为什么没人给我发货？** 插件只记账。请让管理员在插件页"兑换记录"里把记录标记为 `已发放` 并线下发货；标记的那一刻插件会给用户发一条"已发放完成"的提示（私聊或原会话，取决于平台）。

**为什么我（用户）没收到"已发放"提示？** 两种可能：一是这条记录是旧版本留下的、没存发起会话（接口会返回"未通知用户"），二是平台不支持机器人主动发消息。管理员的标记操作不受影响。

**删商品时提示"改为下架"？** 该商品还有 `待发放` 的兑换记录。为了保证历史账目可追溯，插件把删除退化成下架；等这些记录处理完再删即可。

**商品多了以后点"删除"没反应？** 这是 v1.1.0 的历史 bug，v1.2.0 已修：插件页 iframe 的 sandbox 不带 `allow-modals`，浏览器会静默忽略 `window.confirm()`（恒返回 `false`），删除按钮因此永远进不去分支。现在改成页面内确认框，与商品数量无关。若你还看到"点了没反应"，先看顶部状态栏有没有红色报错。

**邮件收不到怎么办？** 按顺序排查：① 配置页「启用兑换发放邮件通知」是否打开；② 点插件页"发送测试邮件"看具体报错（认证失败多半是没填授权码）；③ 收件地址是否为 `<QQ号>@qq.com`（用户没绑邮箱时）或配置里的兜底收件人；④ 看 AstrBot 日志里的 `[打卡商店] 发放邮件未发出` 记录（不会打印密码）。注意邮件失败**不影响**记录状态，用户在会话里仍会收到提示。

**邮件会重复发吗？** 不会。只有记录**第一次**变成 `已发放` 时发一次；重复点"标记发放"既不重复通知也不重复发邮件。

**SMTP 授权码填在哪里？** 插件配置页的「SMTP 密码 / 授权码」，以密码框显示（`secret` 字段双击可见）。它不会写进 `shop.json`。

**删除兑换记录会退积分吗？** 不会。删除只清理历史记录；要退回积分和库存请用"取消并返还"。正因为如此，`待发放` 的记录默认不允许删除，需要再确认一次。

**图片没出来 / 只有文字？** 说明渲染失败（缺 Pillow、字体被删、自定义字体路径写错），插件已自动降级为纯文本回复；日志里会有 `[打卡商店] 图片渲染失败` 的记录。

**在插件配置页改了固定积分，为什么不生效？** 现在会生效：配置页保存后 AstrBot 会热重载插件，插件随即把配置页的值写进运行数据。如果改了没反应，请确认保存的是同一个插件、并且重载日志里没有报错。想让两边完全一致，也可以在插件页改——插件页保存会回写配置页。

## 手动验收清单

本仓库自带测试只覆盖到"插件接线 + 业务逻辑 + 页面接线"，真实平台上的收发消息需要在你自己那台 AstrBot 上跑。建议按下面顺序过一遍：

1. `/打卡` 连续发两次：第一次成功、第二次提示已经打过卡；两次回复都是**一条文字 + 一张图**的消息。换个没打过卡的新账号再发一次，同样要有回复（验证新用户第一次打卡）。
2. 让新账号直接发「打卡」（不带 `/`、不 @ 机器人）：应收到一句"要用「打卡」得先唤醒机器人…"的提示；发「我今天打卡了」这种闲聊则不应有任何反应。
3. 在没有待确认兑换的会话里发「好」「ok」「不」：机器人**不应**回"当前没有等待确认的兑换请求"（v1.1.0 的老毛病）。
4. 插件页改积分模式为"随机区间"，保存；换一天再打卡，看积分是否落在区间内。
5. 去**插件配置页**把固定积分改成别的值并保存：重载插件后再改回固定模式打卡，值应该是配置页填的那个；再把配置页改回**默认值**（固定积分 10 / 固定模式）保存，打卡应按默认值发（验证"改回默认值也生效"，而不是被当成"没改过"）。
6. `/商店`: 确认出图，且"可兑换/暂不可兑换"分组、`还差 N 分` 的提示与后台数据一致。
7. `/商店帮助`: 确认出图，且图里的积分规则与当前后台配置一致（改了配置再发一次，图会变）。
8. `/兑换商品`: 先回一张编号菜单；再发 `/兑换 1`: 机器人给出确认提示；**不引用**直接回"是",应收到"请「引用」机器人那条确认消息…"的提示且积分不变；再**引用那条确认消息**回"是"才成交。
9. 引用确认消息回"是": 积分和库存按预期变化，后台"兑换记录"出现一条 `待发放`。
10. 在后台把该记录标记为 `已发放`: 用户那边应收到一条私聊/会话提示；重复点按钮不会再发一次。
11. 配置 SMTP（`email_enabled` 打开、填服务器/端口/授权码）后点插件页"发送测试邮件": 兜底收件人应收到测试邮件。
12. 让用户发 `/绑定邮箱 你的邮箱` 再走一次兑换 + 标记发放: 该邮箱应收到发放邮件（正文含商品名与兑换单号）；把 `email_enabled` 关掉后标记发放，则只发会话提示、不发邮件。
13. 在后台把另一条记录标记为 `已取消`（勾选退回积分与库存），确认积分库存都回来了。
14. 后台删一条 `已发放` 的兑换记录: 只删记录，积分不变；再试删 `待发放` 的: 应被拒绝，除非确认强制删除。
15. 后台删一个有 `待发放` 记录的商品: 应提示改为下架。
16. 多加几个商品（十几二十个），删其中一个: 确认框正常弹出、确定后真的删掉（验证不再依赖 `window.confirm`）。
17. 插件页上传一张商品图，重新 `/商店`，确认图出现在商品行里。
18. 触发一次渲染失败（例如把 `render_font_path` 指向不存在的文件）：命令仍以文字回复，不报错。
19. 把 AstrBot WebUI 切到深色主题（或直接看系统深色下的插件页）：插件页应当跟着变深色，文字与底色对比清楚；只有宿主既不给主题、系统也判断不出来时才停留在亮色。
20. 把浏览器窗口拖窄到手机宽度（约 420px）：统计卡变成两列，标签页与表格各自横向滚动，页面本身不出现横向滚动条。
21. 插件页故意留空商品名称点保存：字段下方应当直接给出原因并把焦点移到那个输入框，而不是只在页脚提示一句。
22. 在插件页「展示设置」把**指令前缀（仅显示）**改成 `.` 保存：`/商店帮助` 那张图、打卡后的"发送 … 商店"提示、积分/积分榜的空状态都应当变成 `.打卡`、`.商店` 这类写法；同时**照旧发 `/打卡`** 仍然能触发（证明它只改显示）。改回 `/` 或留空，文案回到 `/`。
23. 商品管理页搜"可乐"：只剩匹配行，右侧计数变成「共 N 个 · 显示 1 个」，**序号列不变**；清空搜索后恢复；搜一个不存在的词应出现"没有匹配的商品"空状态。
24. 商品管理页把某一行点成"下架"，再回到群里发 `/兑换商品`：菜单里**不应**出现它，而其它商品的编号**不变**（下架不挪号）；再把顺序上下调一调，菜单与 `/商店` 图里的编号应同步变化。
25. 群里只发 `/兑换商品`（不带参数）：应回一张纯文本编号菜单（不是图片）；照着发 `/兑换 2`，确认提示里的商品名应与 2 号一致；发一个不存在的编号（如 `/兑换 99`）应回"没有 99 号商品"并提示怎么看最新列表。
26. 打完卡再去后台「账单流水」：应看到一条 `打卡` 收入，余额与「用户积分」页一致；再走一次兑换（含取消返还）与一次"调整积分"，四类记录都应在流水里，且「变动后余额」逐条接得上。
27. 「账单流水」按类型选 `兑换`、关键词输用户昵称：表格与右侧"筛选结果"汇总应同时收窄（汇总算的是筛选后的全部记录）；点「导出 CSV」下载的文件应当只有筛选命中的行，用 Excel 打开中文不乱码。

```bash
python -m pytest

# 插件页接线（需要 Playwright；脚本也会直接找本机 Edge）
node tests/test_page.cjs

# 想人眼看一遍插件页时：额外把 5 个标签页 + 深色 + 窄屏 + 弹窗/空状态截图写到 docs/ui-review/
PAGE_REVIEW=1 node tests/test_page.cjs   # PowerShell: $env:PAGE_REVIEW=1; node tests/test_page.cjs
```

测试覆盖：当前 `pytest` 200 项、页面检查 41 项全绿。时间与逻辑日切换、JSON 存储的原子写与并发、打卡与兑换的边界分支、配置页与插件页的双向同步、发放通知的私聊/回退分支、SMTP 邮件（收件地址解析、SSL/STARTTLS/明文三条分支、失败提示、以及**真实起一个本地 SMTP 服务器**做投递闭环）、Pillow 出图（含"内置字体不缺字"检查、帮助图排版、以及"**四张卡片的所有文字都必须落在最终图内**"的越界检查——卡片会按内容裁切，这条闸门能挡住"排版改完把内容画出图外"）、以及用最小 AstrBot 桩验证指令注册、引用解析和"发起兑换 → 引用确认 → 扣分扣库存"的完整闭环。确认逻辑另有专项用例：没有待确认请求时"好/是/ok/不"必须静默、没引用时给可照做的提示且不动数据、超时只在引用对得上时提示、会话标识变化后仍能确认；打卡侧则锁定"全新用户第一次打卡必须有回复且写入积分""存储出错必须回一句失败原因""裸指令必须给提示而不装死"。展示前缀（`display_prefix`）也是专项覆盖：留空回落 `/`、超长截断、提示语/帮助图/卡片/裸指令提示/邮件提示全部跟着变、**不改指令匹配**、接口超长报错、插件页保存会回写配置页、以及"前缀进缓存键"（改前缀必须重新出图）。`tests/test_page.cjs` 会起一个临时静态服务器加载插件页，用假的 bridge 驱动六个标签页（含删除商品/兑换记录、测试邮件、显示前缀的默认回填与提示跟随、流水的筛选与导出）并把页面截图存到 `docs/page.png`；其中删除相关的用例会**把 `window.confirm` 替换成抛异常**，确保页面不再依赖它。页面检查另外覆盖排版节奏、KPI 等高等宽、表头吸顶与数字列右对齐、长名省略号、空状态、异步按钮防重复点击、提示条"成功自动消失 / 失败常驻可关"、弹窗按钮顺序、420px 窄屏不横滚，以及**亮色/深色正文与次要文字的对比度 ≥ 4.5:1**（含"宿主下发 `data-theme` 优先于系统 `prefers-color-scheme`"）。商品编号（序号）同样是专项覆盖：编号规则与两位补零、下架不改号、菜单文本与不可兑换原因、`2`/`02`/`#2`/`第2个`/`2号` 这些写法、越界与"编号指向下架商品"的两种不同说法、菜单按展示前缀出写法、菜单过长只列前 N 个；页面侧则锁定"序号列 = 接口返回的 number""筛选与排序都不改序号""搜索/分类/状态筛选与空状态""点状态 pill 提交完整商品对象""上移下移提交的 order 顺序"，以及"编辑已有商品不会把它挪到列表最后"。账单流水是新增的专项：`append_ledger` 的"变动后余额"取的是改完之后的余额、超出 1000 条裁掉最旧的、打卡/兑换/返还/调整四条写入路径（含"取消兑换重复点不重复返还、也不重复记流水""调整失败不写流水"）、时间边界的四种写法（`2026-09-21`、`2026-09-21 23:13`、秒级与毫秒级时间戳，日期上界含当天）、关键词命中昵称/QQ/备注、类型白名单外当"全部"、分页与"汇总按筛选后全部记录算"、CSV 的 BOM / 表头 / 逗号转义；接口侧覆盖"流水列表与汇总""导出 CSV 走 query 筛选""打卡与兑换真的各落一条流水，余额首尾相接"，页面侧覆盖"流水表渲染与收支颜色""按类型与关键词筛选 + 空状态""导出按钮把当前筛选带进 download""日期区间筛选与分页禁用"。

## 打包发布

```bash
# 产出 ../astrbot_plugin_checkin_shop-v1.2.0.zip（默认打在仓库上一级，避免产物混进源码树）
python scripts/build_release.py
```

压缩包按 AstrBot 的安装逻辑组织：`metadata.yaml` 位于**压缩包根目录**（安装器据此识别插件与目录名），`name` 是合法 Python 标识符。包含运行所需的全部文件——代码、`pages/shop` 插件页、`_conf_schema.json`、i18n、内置字体与 OFL 许可；**不包含** `tests/`、`scripts/`、`docs/`、`pytest.ini` 等开发文件。

打包脚本会立刻回读产物自检：元数据必填字段、schema 可解析、关键文件齐全、字体在位、无缓存文件混入。
